# ADR 0026 — A reachable backend, and the instrument that could not decide it

**Accepted — decided, not built.** Answers whether a backend is ever reachable
from a shipping command, and withdraws ADR 0011's performance ladder from the
role of deciding it. **A backend has since shipped**, on the authorisation
below.

**Read this line first: nothing here *decided* to ship a backend.** This
project's most expensive defect class is a mechanism named everywhere a reader
would look for it and constructed nowhere, **and a record that decided a backend
was reachable would be the largest possible instance of it.** What is decided is
the *question*: whether the answer is ever yes, on what evidence, and against
which instrument.

## Context

**A large speedup was measured and no user of Ply could reach any of it.** The
kernel record is blunt about it under a heading of its own — *nothing here
ships, and that is the load-bearing sentence.* The shipping differential command
could not install a backend, so it caught **zero** of the eight deliberately
wrong backends the mutation harness runs, and the rule that a backend run must
not populate the result cache was **unenforced because it was unreachable.**

**And the deferral was ordered by an instrument that cannot be pointed at any
workload but one.** The ladder decides from the interpreter's share of a served
HTTP request over TLS over a database, and **refuses a ladder without all nine
of its rungs** — so a compute kernel, or a lexer over a file, cannot be fed to
it at all.

## What is true, checked rather than quoted

**The seam was unreachable, and the record's inventory of it was stale.** The
count of call sites was wrong by an order of magnitude, and a second document's
list summed to a third number while omitting a file. **The load-bearing half is
unaffected and was re-checked one file at a time: every call site is a test or
the spike's harness. The count was decoration on a claim about *reachability*,
which is why nobody noticed it was wrong for four days — and that is the point
of correcting it. A number carried beside a true sentence is still a number a
reader will re-quote.**

**The seam is not inert on the shipping corpus.** Two hand-built backends
attached to the machine over the workspace corpus show **about a sixth of
offered calls clearing every gate on real Ply source.** So it is not a
hypothetical surface waiting for a workload that never arrives — **and it is
what the differential command would be auditing if it could.**

**The spike's published figures were stale on both of theirs**, the second in
the direction that matters: a lint claim used to justify not linting it in CI,
which re-taken is clean. **Two documents disagreed about the same crate, and the
one nobody re-took was wrong** — which is what the stale-figures note itself
predicts.

**One property of the seam decides how far the evidence reaches, and it is easy
to miss because it is stated as a safety rule rather than as a limit**: it
admitted only integers and booleans, which its own comment calls *a capability
cut as much as a safety one.* **So the seam as it existed was a scalar seam** —
the right cut for the code generator behind it, since the fragment lowered
arithmetic as integers whatever the operands were, so a float crossing would be
a working program that starts raising at a call site nobody opted into — **and
the reason the kernel result is a fact about integer compute and cannot be
extrapolated to an HTTP request, independently of any share.**

### The function the whole projection rests on cannot cross the seam

The ladder's speedup is measured on the request-path function with the highest
per-request cost whose entire body is inside the fragment. **Its argument is
bytes and so is its return, so it is refused on argument shape, before any gate
that has anything to do with effects or budgets.**

The spike's ratios are real, and its own source says which path they are taken
on: *a direct native call, **outside any machine***. The harness holds a machine
with a backend attached, **and that is not what the ratio is taken on.**

**So the projection is Amdahl applying, to the whole interpreter share, the
speedup of a function that the seam as built cannot enter.** Not a number
unreachable pending a wiring change — **the argument shape is refused by the
boundary's first line. The served-HTTP arm of the ceiling criterion is not
"never measured"; it is not measurable through this seam at all**, and would
stay so after any amount of CLI work.

**This is also the cleanest illustration of the whole point: the ladder's
speedup and the seam's reachability were built by different milestones against
different questions, and nothing in the tree compares them, because no
instrument takes both.**

## The instrument cannot answer the question it is being asked

**Nine fixed rungs, and a refusal.** Demonstrated by deleting one rung from a
copy of the shipped ladder: the tool answers *undecided — the ladder carries no
database rung, so its total is not the stack's and no share can be read off it.*

**The decision procedure structurally requires a served HTTP request with a
socket, a TLS record layer and a database round trip. A compute kernel cannot be
fed to it. Not "has not been" — cannot be, by the type.** That refusal is
correct for what the ladder is: a share over a partial stack is a share of the
wrong denominator. **The defect is in reading the output of a nine-rung HTTP
instrument as an answer about a language.**

**The verdict is decided at the nothing-cheaper criterion, and the share tests
are never reached.** Re-derived by running the tool over both published pairs:
it returns inside the unpriced-lever block, **before every share test there is.
Nothing about the interpreter's share has decided anything in either take.**

**The share has already crossed the ladder's own categorical floor** — the whole
band is below it, so it does not even straddle. Demonstrated by marking the
unpriced levers priced in a copy outside the tree: the verdict becomes *below
the floor: even an infinitely fast backend is worth less than the bar.* **That
branch is already live. The unpriced levers are the only thing standing in front
of it.**

**The ratchet is real and is not the criterion the record names.** Between the
two ladders, with no regression recorded anywhere, the share fell, the
projection fell, the ceiling fell, **and the speedup a backend needs rose by
more than half again. The bar moved away from the backend while the backend
stood still.** But **the interpreter did not get faster between the two ladders
— it got *slower*, and so did the whole request, by more. The share fell because
the rest of the request grew faster than the interpreter did.**

So the share is a ratio whose denominator contains a TLS record layer and a
database round trip, **and it moves with facts that have nothing to do with Ply.
A slower disk lowers the case for a backend. A faster TLS library raises it.**
The portable readings are ratios and not microseconds, which is right about the
ladder's *rungs*; **it does not follow that a ratio between an interpreter and a
network stack is a portable statement about an interpreter.**

**The ceiling criterion is not the ratchet. The share criterion is.** Run as a
counterfactual with every lever priced and the spike's times divided until the
ceiling clears, **the reopen sentence collapses to one clause: the share
reaching its bar.** That asks the interpreter to become half of a request, and
**the only thing that does that is the interpreter getting slower or the
database getting faster. A criterion satisfiable only by a regression or by
somebody else's release notes is not a criterion.**

**And there is barely a point left before the criteria become unsatisfiable at
an infinite speedup.** The measured share is just above the point below which
the ceiling is arithmetically impossible however fast the fragment runs. **One
more lever the size of the constant memo — which halved the share on its own —
puts the ladder in a state where it prints a bar that no backend in any universe
can clear, in the same sentence and the same tone as a bar that a good backend
could.**

### What is *not* wrong with the ladder

Stated because most of it is kept, and because a document that only listed the
defects would be dishonest about a measurement this project paid for twice.
**The thresholds are right for the question the ladder asks.** **The
nothing-cheaper criterion has never been a ratchet** — it compares *gains*
against *gains* on the same workload, **so the instrument's denominator
cancels**, it has fired every time and for a good reason each time. And
**keeping the verdict out of the report worked**: *a verdict that can be written
into a file will eventually be written into a file* is why every number above
could be re-derived by running a binary over a shipped file rather than by
trusting a sentence. **That property is what made this section possible and it
must not be lost.**

## What an interpreter share can settle, and what it cannot

**What it settles.** On the workload the ladder was taken on, the interpreter is
about a third of a request, so no execution-strategy change is worth much end to
end on *that* workload. **Re-derivable by one command over a shipped file, and a
sufficient reason not to put a code generator in front of Ply's HTTP stack.
Nothing below disturbs it.**

**What it does not settle.** Whether Ply should have a compiled backend is a
question about what Ply is for. **A number that requires a database rung in its
denominator cannot be evaluated on a workload with no database, and the
instrument answers *undecided* rather than extrapolating — correctly.** On the
one non-HTTP workload anyone has measured, three of four criteria would pass.
**There is no code path in this tree that computes that.**

### The basis, stated so a reviewer can reject it directly

The framing this work was commissioned under describes Ply as *a compiled
language carrying the workloads Go, Java and Swift carry*. **That sentence, or
anything equivalent, is in no file in this repository**, checked with a grep
across every top-level document — the README opens *"It is a research
language"*. **Deciding from that framing would reproduce, one document later,
the exact defect ADR 0021 was written to fix: a rationale that existed only in a
conversation, leaving the next reader a rejection with no goal behind it.**

**So the target is not the basis. What is, and it has nothing to do with an HTTP
request's interpreter share: ADR 0021 puts compiled entry on the critical path
of a record accepted as a statement of intent** — *the fragment, entered at
token granularity*, on a profile where dispatch dominates builtin bodies by more
than an order of magnitude, **so compilation removes the right half. The reason
to want a backend that is written down in this tree is the bootstrap track, not
throughput on a served request — and the ladder cannot see it at all**, because
a lexer over a file has no socket, no TLS and no database.

Two limits rather than support. **The kernel result is corroboration and is not
the reason** — one kernel, one box, one pre-registered run whose own
pre-registration forbade re-running, through a scalar seam. **Had it come back
small, the answer would read the same and the ceiling criterion is what would
have stopped it.** And **that critical-path item's own unmeasured half is
unmeasured still**: the cost at one entry per token, whose nearest answer lives
in three deliberately-ignored tests inside the crate the ladder's record wants
deleted.

**If a reviewer rejects that basis** — because the bootstrap track is
speculative, or because a token-granularity entry is not the same thing as a
backend a user reaches — **the answer weakens to "not decidable here", and
everything else stands, because each rests on a measurement rather than on a
goal. That is the intended failure mode: it is separable.**

## Decisions

### Yes, a backend is reachable from a shipping command

On that basis and no other. **The question the record has actually been
answering is narrower — should this HTTP service have a code generator — and its
answer is no, is well measured, and is untouched by anything here.**

Three things this is not. **Not "advance the milestone"** — the verdict below is
defer. **Not a claim that a backend is close** — the function the entire HTTP
projection rests on is refused on its first line. **Not permission to promote
the spike.**

**What changes is the standing of the question.** The milestone has been
deferred by an instrument that structurally could not consider the case for it;
from here it is deferred by **two obligations that name work, and neither is a
number that must rise.**

### The ladder is withdrawn from deciding it

**Not withdrawn as a measurement** — it remains the best account of where a
served request's time goes. **What is withdrawn is its authority**: it refuses
every workload but one, its share moves with the network, and its reopen
sentence names a criterion only a regression can satisfy.

**A ratchet may not be left standing while a decision is taken around it**, so
this is a change to code: the verdict and reopen strings name *a code generator
for the served HTTP workload*, not the milestone, and the decision carries the
workload its share was taken on, **so that "a third of a request" cannot be
re-read as "a third of Ply". After that the ladder's answer is the same and is
true. It simply stops claiming to have decided a question about the language.**

### The criteria that replace it, and each of them can fire

**The single structural change is that a verdict names a workload class.**
**The earlier mistake was not its thresholds but its assumption that one
workload could stand for the language.**

**Coverage, measured as work rather than as time** — the fragment accepts at
least half the workload's *executed work*, counted in executed lowered nodes.
*Why*: a work share does not move when the interpreter gets faster at the same
work, and **does not move at all when TLS or the database gets slower, which is
what actually moved the old share.** It moves when a lever *deletes* work,
**which is honest: a backend genuinely has less to do** — and it is satisfiable
by widening the fragment. **The threshold is inherited rather than re-derived,
which is the weakest line here**: the old justification was about a **time**
share and does not transfer unchanged. **Provisional**, and what would settle it
is taking both shares on one workload and reading the difference.

**A delivered speedup, not a projection**, with a backend attached and native
entries counted, against a control arm at zero entries. *Why*: the projection's
own record lists three measured reasons to doubt it, and **a projection its own
author calls "an upper bound with three measured reasons to doubt it" may not
clear a gate.**

**Nothing cheaper — kept, with one word changed.** The list is the *workload's*.
*Why kept*: **the only one of the four that was never a ratchet**, satisfiable
by measuring rather than by waiting, and right every time.

**Correctness, with measured sensitivity, through a shipping command.**
Agreement on every input, **and** the corpus must have been *seen to fail*,
**and** the wrong backends must be caught by a command a user can run. *Why
strengthened*: **"zero disagreements" is the exact shape of result this project
names as its most expensive defect class**, and the old clause is satisfied by a
corpus that compares nothing.

**Where they stand: defer, for both classes**, on nothing-cheaper and
correctness. **The difference from every previous deferral is the shape of what
is owed: one is a measurement somebody can take next week, and the other is the
contract below. Neither asks a ratio to move on its own, and neither can be
satisfied by a regression.**

**A third workload class is named and not judged, deliberately: the bootstrap
front end.** It is the recorded basis, and no row is offered, **because writing
one would be the vacuous green this project keeps producing.** Taking that
measurement is the highest-value item this does not itself require, **because it
is the one workload where a positive answer would order the milestone against
something already accepted rather than against a preference.**

The sensitivity does exist at corpus scale and was re-taken rather than quoted:
zero disagreements over thousands of cases, and **over a thousand under a
mutation, exiting non-zero.** One blind spot is carried forward: **a
whole-program search is a weak oracle** — every compiled function except a
search's entry points is offered zero times, because the hook sees nothing under
an entered root. **A future harness that ran only whole-program searches would
report the same green over a much smaller explored space.**

### The contract: a backend must be policeable before it is fast

**No backend may ship until the shipping differential command can attach one and
catch the eight.** Not because policing is more valuable than speed, but because
it is *upstream* of it: **a backend whose wrong answers no shipping command can
detect is not a backend that can be shipped at any ratio.**

**The differential becomes three pairs**, which the cost accounting priced
correctly as a permanent cost. **What it could not price is what it buys**: a
sixth of six figures of offers clear every gate on the workspace corpus. **A
third pair over that corpus is a real oracle on real source, not a ceremony.**

**The wrong backends must be catchable from the workspace, without a code
generator.** Every one is a wrapper over the seam's entry point, and the
workspace already holds two backend doubles. **The mutations do not need a code
generator; they need something that answers** — and the tree-walking double
answers. (The declining double is the control: it answers nothing, so it can
host no corruption — **which is exactly why a harness must assert the offer
count before it asserts the catch.**)

**Two will not move unchanged, and saying which is the point of naming them.**
The published-row mutant **cannot be produced by a backend at all**, so what
stands is an offer count of zero. The unbounded-budget mutant is a native stack
overflow, **caught only from outside the process**: any workspace harness must
run it as a child, **or it will report the most catastrophic failure available
as its quietest.** And **one is not caught where a reader expects**: a wrong
*type* leaves the refusal counter at zero, because both scalar kinds cross. **A
harness that watched that counter for it would watch a counter that never
moves.**

**Built, and the clause is met for two backends rather than one.** Under the
differential the backend is a **third** engine compared against the plain
machine rather than against the tree-walker — **so a divergence reported is the
backend's and nothing else's.**

**The clause is discharged per backend, not per seam, and that is why the table
is run twice.** The first implementation was reached only through a concrete
type, **and two of the eight need operations the seam's trait does not have**:
one asks the registry whether a body exists, which is the distinction between
*declined* and *never had one*, and one re-runs the body with fuel that is *not*
the machine's budget. **What a corruption can bite depends on which definitions
the backend has a body for, and the two fragments are very different**, so the
counts are reported separately.

**The tree-walking backend catches seven of eight; the code generator accounts
for eight.** The eighth is the unbounded runaway, **caught by the process dying**
— in hundredths of a second with a signal, where the tree-walker produces no
output and no exit for a minute. **The test asserts the child died *by signal*
rather than merely failing**, because the weaker assertion was watched passing
under a deliberately emptied fragment while nine other tests went red.

### The cache rule is armed before a backend exists, not after

The seam's comment states the rule and, unusually, states its own
unenforceability in the same breath. **Verified by reading every candidate: the
enum that decides cache bypass knows nothing about a backend, the arguments have
no field that could carry a machine, and the fact that would answer had no
caller outside tests. The rule was unenforced twice over: the flag that would
set it did not exist, and the fact that would detect it was never read.**

**Note the interlock, because it is a trap:** the differential mode already
implies no cache, **so a backend installed on that path would be cache-safe *by
accident*, while one on the default path would not. Enforcement may not be that
accident.**

Two stages, the first landing before any backend. **A tripwire over *production
source* rather than over behaviour**, failing when the installer acquires a
production caller unless the bypass inputs have grown a way to see it — **which
converts a rule stated on a doc comment into a test that fires on the exact
change that would break it.** And **a diagnostic, owed by the milestone and
specified here so it cannot choose a weaker shape**, on the model of the
existing host-boundary rule: walk the finished report and turn a cached pass
whose test entered compiled code into an internal error. **The one-line version
covers only a backend that arrives by the flag; the specified version survives
one arriving by any route, and the reason to specify it now is that stage one
alone would let the milestone ship the cheap version and call the rule
enforced.**

**Both hold against a code generator — but "it must still hold" is exactly the
sentence the contribution rules are about, so each was broken again rather than
reasoned about**, including checking that the production-source scan **reaches a
crate that did not exist when it was written.** **One defect was found by doing
this rather than by reading**: the two halves were first one test over one
directory, and the read half warms the cache, so the write half found the passes
left by the warming and **reported a failure on a tree where the rule holds
perfectly.**

**The cache-key objection lands on the flag half and is not answered here.** An
opt-in code generator is an opt-in cache, **and that shape was already refused
for the host flag on the grounds that the checker must not disagree with
itself.**

### The spike: one clause honoured, one amended

*It may not be kept because it works. It is thrown away whatever the verdict.*
**Honoured literally.** The spike has bit-rotted twice while nothing noticed,
**and the path to a shipping component does not run through it.**

**The authorisation to take a code generator into the shipping workspace was
exercised.** What still holds: **no workspace toolchain moves**, because the
pinned version declares a minimum already met — **and the next minor requires a
newer compiler and is deliberately not the route.** The spike is not promoted:
still not a workspace member, still depended on by nothing, and the new crate
does not import from it. **What moved is source**, copied with provenance —
**a new crate built from a spike's source is not the spike being kept because it
works; it is the spike being read.** And **policeability was met before speed
was argued.**

**The deletion clause's stated reason was already false before that change.**
After entry landed, the evaluator carries the seam — a public trait, an
installer, counters and a branch on every interpreted call — **all of which
survive deleting the spike. Performing the deletion removes the only
implementation and leaves the declaration standing, which makes the
declared-nowhere-constructed shape *worse*, not better — and the
production-source scan does not reach traits, so nothing in the tree would say
so.**

> **Amended.** The spike is deleted when — and only when — the seam's **measured
> sensitivity** exists inside the shipping workspace: the eight reproduced over
> the workspace's backend doubles, under the ordinary test command, **with a
> corpus that has been seen to fail.** Until then the spike is the only thing in
> this repository that has ever demonstrated that a wrong backend would be
> noticed.

**The condition failed once, for a structural reason a caveat had predicted.**
Seven configurations moved and were **stronger** on the axes that moved. The
eighth did not: it was called *a native stack overflow, caught only from outside
the process*, **which is true of native code on a fixed stack and false of a
tree-walker whose frames grow on the heap. The same corruption does not crash
there — it hangs.** A harness can run it as a child; **what it cannot do is tell
a hang from work, and a wall clock is not a disagreement.**

**The condition is met now, and the spike is still not deleted. Both halves of
that sentence are decisions.** A code generator supplies the missing half —
**and the earlier diagnosis was half wrong about which half was missing: the
reporter was never absent**, since every backend test runs the CLI as a child.
It is not acted on for two narrow reasons meant to expire: the spike is the only
home of **a measurement that is currently red and unexplained**, and **deleting
the crate deletes the evidence for an open finding before anybody has decided
what it means**; and the kernel ratio has no other instrument.

**This is a permission, not a schedule, and it has expired once before. This is
the third document to touch this obligation, and that is a reason for suspicion
rather than for confidence.** The difference claimed, and it should be held to
it: **this one names a condition, and the condition is a test somebody writes.**

### The seam stays

Stated as a decision because "delete the spike" is routinely read as implying
it, and the two are different acts.

1. **It is the answer to an architectural question, and the answer was
   measured.** *Make the interpreter able to enter compiled code, or the ceiling
   holds however much of the fragment you accept.* Entry turned parity into a
   large win and withdrew its own ceiling as an artifact of a body-only
   attribution.
2. **Its contract cost four review rounds to get right and every round is
   recorded in it**: the frame bound that let a backend answer where the machine
   raised; the effects gate and the transitivity a one-hop bit does not give;
   the arena reset; the refusal of floats in front of a fragment that lowers
   arithmetic as integers. **Deleting the seam deletes the tests that hold
   those, and the next backend rediscovers them by review or does not.**
3. **It costs zero allocations per request**, measured against a binary with the
   call site deleted.

And the honest cost of keeping it: **the wall clock of the per-request branch
tests has never been taken**, on either of two binaries that both existed.
**Zero allocations is not zero cost.**

## What the code generator reaches, and what it costs

**On the front-end-shaped workload it is a net loss** — the front end was
predicted to be the worst case and is worse than that prediction. **Both corpora
are green under the differential with it installed**, which is the correctness
result and the reason the speed rows are worth reading.

**The pre-registration** fixes five statistics and their decision rules,
**including two written to permit an unwelcome answer**: zero entries is a null
result reported as one in the first sentence, and a result at or below the
tree-walking backend's is the *predicted* outcome, reported as a confirmation.
**No arm is re-run to get a better number.**

**The finding is the contrast between two corpora.** On a compute kernel the
code generator reaches exactly what the tree-walking backend reaches — the
fixpoint refuses *nothing*. On a program built out of the standard library it
reaches about one percent of offers, and the census says why, ranked: **string
concatenation, the fold, the map, a lambda. That is the kernel record's roadmap
re-derived on the shipping standard library, four milestones later, unchanged in
its ordering.**

**The cost splits because the halves scale differently** — the analysis is
whole-program and paid once, **the code generation is paid per worker**, because
a compiled unit owns a constant pool of values and a value is reference-counted
all the way down.

**Every speed series was taken above the load gate. These are observations and
not figures. What makes the ordering safe anyway is the null control, which is
in the series rather than argued.** The kernel arm is **the first speedup from
compiled Ply code a user can reproduce with a documented command**, and is a
different measurement from the spike's body-only ratio. **The workspace-corpus
arm is several times slower than no backend: per-run compilation costs more than
the ceiling is worth there.**

**That magnitude does not transfer, and the correction is in this record's
favour.** An adversarial re-take, rotating one slot per window so a position
effect and an arm effect cannot be confused, added the missing row: **on the
real front end it is a few percent slower, not several times slower.** The large
loss is an artefact of corpus length — **that run is short enough that the fixed
cost *is* the window. The sign is right; the magnitude is not transferable.**

**What actually costs it the front end is the fragment, and it is narrower than
the tree-walker's** — well under half as many entries, **exactly the figure ADR
0030 names as the pre-widening scalar rung. So it reaches less than half of what
the seam's tree-walker reaches on the workload the bootstrapping goal turns on.
That is a fourth route out and it is not on the list below: widening the code
generator's fragment to what the tree-walker already reaches. It is the only one
of the four whose size is known in advance.**

**Three routes that would change the loss, none measured, named so the next
change starts from a list rather than from the number**: compile fewer
definitions, since only definitions reachable from an enterable one can ever run
— **it needs a call graph the fixpoint currently discards**; compile once
instead of once per worker, blocked because **a value is reference-counted**;
and compile lazily on the first offer, cheapest and least helpful here.

**None of this is a reason to have deferred.** The whole argument is that
policeability comes before speed. **A slow backend that is checked is the thing
this record asked for; a fast one that is not is what it refused.**

## What this does not decide

**Which backend** — the criteria are written against an implementation of the
seam's trait. **The cache key** for a world where a backend is the normal path.
**Determinism**, named as the sharpest cost: a backend that reassociates
arithmetic or reorders argument evaluation breaks seeded replay and tier honesty
**silently**, and the present seam evades it by being off inside a simulated
region and handing back at most one scalar — **a backend that matters will not
evade it, and nothing here says how it is checked.** **The toolchain**: the
milestone forces a version *choice*, not a move — **read off the index per
release, and then run rather than read**, by compiling and *calling* a native
body through the older version, **with the check seen to fail before it was
believed** — but **a lockfile entry is not conditional on a feature**, so dozens
of packages enter the shipping lockfile even with the crate excluded. **And
whether the kernel ratio holds anywhere else.**

## What must be built, and the test that says it happened

In dependency order, each naming the artifact that makes it checkable, **because
a decision recorded without one is what the amendment above is trying not to
repeat.**

1. **Stop the ladder claiming the milestone, in code.** The prose half is done.
2. **The cache tripwire**, with **non-vacuity demonstrated** by adding a
   production installer call and recording that it goes red, in the file's own
   header.
3. **The eight mutants in the workspace**, over the backend doubles, **with the
   offer and answer counts asserted before the catch is asserted** — the middle
   step usually missing.
4. **The spike is deleted** the day 3 lands.
5. **Nothing-cheaper on the compute kernel.** Price the missing prelude
   builtins end to end — **the current figure is inferred by Amdahl over three
   fields of one file and is not a measurement** — and re-take the
   map/record/list share on a hybrid run rather than on the pre-entry
   attribution it rests on.
6. **The correctness clause's third half**, the milestone's own first task.
7. **Coverage and speedup on the bootstrap front end**, **the one workload where
   a positive answer would order the milestone against something already
   accepted.** It needs no CLI work and no backend the seam can enter today.
8. **If the compiled-workload target is real, write it down.** ADR 0021 exists
   because a rationale that lives only in a conversation leaves the next reader
   with a rejection and no goal behind it, **and this record was nearly the same
   failure one document later.**

## What would make this wrong

- **The replacement coverage criterion is a work share, and nobody has taken one
  on an HTTP request.** The kernel's is a **body-only accounting — the same
  accounting that produced a *wrong ceiling***, because it charges the call-site
  machinery to a bucket that entry also deletes. **If a work share is
  systematically wrong in the same direction, this is a bar that passes things
  it should refuse, and it is the criterion this record moved. This did not
  check it.**
- **The basis rests on one item of one record that decides no implementation.**
  If the bootstrap track is abandoned, **the answer reverts to "not decidable
  here".**
- **The commissioning framing is not in the tree, and it would have carried the
  decision if it had not been checked. If a later revision quietly restores it,
  that revision is the defect.**
- **A ratio is not a product decision.** A large speedup on a kernel **may leave
  Ply in the same place relative to the language a user would otherwise pick.
  There is no criterion for that at all, and adding one is not obviously
  possible.**
- **The mutation harness may not survive the move**, in which case the deletion
  condition will have been satisfied on paper by something weaker.
- **The whole-program oracle is weak, and the replacement correctness criterion
  may inherit that.**
- **Keeping the seam may cost something nobody has measured.**
- **And the ordinary way**: if the list above is still unbuilt in six months,
  **this will have been a fourth document about an obligation instead of the end
  of one. A reader who finds the spike still present and item 3 still unwritten
  should treat this document as the defect.**
